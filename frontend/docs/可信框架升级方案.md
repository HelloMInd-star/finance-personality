### 关键缺口（本次升级要补的）

1. **可信能力分散**：熔断/审计/阈值散落在 MindSpeak、fuse、dispatcher 各自引擎里，**没有统一的总控收口层**，金融看板使用的决策（`dispatcherEngine`）**未接入三角审计与七层熔断**。
2. **无 S0-S9 闭环流水线可视化**：ymine 的十步闭环（宏观海选→清洗ETL→定价估值→沙盘推演→周期观测→人性校验→调参→审计→熔断→同步）在本项目没有对应 UI 与状态机。
3. **审计/熔断无总控仪表盘**：fuse 状态、三角审计结果、全局三线（保本/稳态/熔断）没有统一仪表盘展示。
4. **看板决策无 gate 门控**：看板的“执行/放弃”推荐没有经过熔断+审计门控。

## 二、升级目标

把本项目看板升级为 **Game-OS 可信决策中台**，核心是四个“统一”：

1. **统一阈值**：三线（0.48 保本 / 0.50 稳态 / 0.68 熔断）作为唯一常量被所有引擎引用。
2. **统一门控**：每个决策输出前，先过 **三角审计 → 七层熔断 → 门控放行**，不通过则标记 blocked。
3. **统一流水线**：S0-S9 十步闭环状态机，展示每步的输入/输出/状态/审计。
4. **统一总控台**：一个仪表盘聚合 全局三线 + 熔断状态 + 三角审计 + 流水线进度。

## 四、统一阈值常量（trustState.js）

把散落的阈值统一收口，所有引擎引用此常量：

```js
export const TRUST_THRESHOLDS = {
  BREAKEVEN: 0.48,   // 保本底线
  STEADY_MID: 0.50,  // 稳态中轴线
  FUSE_RED: 0.68,    // 熔断警戒线
  TRIANGLE_TOLERANCE: 0.02, // 三角审计容差
  // 与 fuse.js THRESHOLDS 保持同源，避免两处漂移
};
```

> 说明：`fuse.js` 已有 `THRESHOLDS`，本方案**以 trustState 为唯一真源再导出**，逐步替换散落硬编码，避免双源漂移。

## 五、可信门控层（trustGate.js）

核心：**任何决策在放行前必须串行通过“审计→熔断→门控”**。

```js
// 十步闭环步骤定义
export const PIPELINE_STEPS = [
  { id: 'S0', name: '宏观海选',   icon: '🌊', phase: 'auto' },
  { id: 'S1', name: '信息清洗ETL', icon: '🧹', phase: 'auto' },
  { id: 'S2', name: '核心定价估值', icon: '⚖️', phase: 'auto' },
  { id: 'S3', name: '沙盘决策推演', icon: '🔮', phase: 'auto' },
  { id: 'S4', name: '动态周期观测', icon: '📈', phase: 'auto' },
  { id: 'S5', name: '人性偏差校验', icon: '🧠', phase: 'manual' },
  { id: 'S6', name: '人工调参确认', icon: '🔧', phase: 'manual' },
  { id: 'S7', name: '审计复核',     icon: '🔍', phase: 'manual' },
  { id: 'S8', name: '熔断风控对冲', icon: '🛡️', phase: 'manual' },
  { id: 'S9', name: '全局同步闭环', icon: '🔄', phase: 'sync' },
];

// 三角审计三模型（复用 mindspeakEngine 的设计）
export const TRIANGLE_ENGINES = [
  { id: 'CALC',  name: 'CALC 金融精算',   icon: '💰', fn: calcScore },
  { id: 'GAME',  name: 'GameMind 博弈',   icon: '♠️', fn: gameScore },
  { id: 'GEOM',  name: 'geom-compute',    icon: '📐', fn: geomScore },
];

// 解码时读取熔断状态：若熔断激活，所有 downstream 步骤标记 blocked
export function gateDecision(decision) {
  const fuse = getFuseState();
  if (fuse.active) {
    return { ...decision, blocked: true, gate: 'FUSE', reason: fuse.triggerReason };
  }
  const audit = triangleAudit(...); // 三模型并行
  if (!audit.passed) {
    return { ...decision, blocked: true, gate: 'AUDIT', maxDev: audit.maxDev };
  }
  return { ...decision, blocked: false, gate: 'PASS', audit };
}
```

**门控规则**：
- 熔断激活 → 直接 `blocked=true`，gate=`FUSE`，阻断所有输出。
- 三角审计未通过（maxDev>0.02 或任一模型为 0）→ `blocked=true`，gate=`AUDIT`。
- 两者通过 → `blocked=false`，gate=`PASS`，可放行。

**S0-S9 状态机**（`runPipeline`）：每步记录 `{ id, status: waiting|running|passed|failed|blocked, input, output, audit, at }`，写入 `draft` 分区；S9 成功后 `commitPipeline` 到只读 `pipeline` 分区，写 HMAC 审计日志。

## 六、看板接入（InvestBankDashboardPage.jsx 改动）

在现有真实数据模型基础上，把决策中枢的推荐接入门控：

1. **构造流水线**：把看板已有计算（估值→沙盘→VaR/CVaR→画像匹配→决策）映射到 S0-S9 步骤，实时生成每步状态。
2. **决策门控**：`generateDispatchDecision` 的推荐结果经过 `gateDecision`，未通过时推荐区显示红色阻断标签 + 原因。
3. **流水线 UI**：在决策区下方新增 S0-S9 横向进度条（passed=绿 / running=蓝 / blocked=红 / waiting=灰），半自动化步骤（S5-S8）可点击展开审计明细。
4. **审计面板**：展示三模型独立评分（CALC/GameMind/geom）+ maxDev + 容差，复用 `MindSpeakPage` 的 `TrianglePanel` 样式。

## 九、风险与说明

- **复用而非重写**：三角审计与熔断已存在，门控层只做“编排收口”，不重复实现算法。
- **阈值同源**：`trustState` 与 `fuse.THRESHOLDS` 需保证一致，避免两处漂移导致熔断/门控不一致。
- **StrictMode 双挂载**：接入真实数据时沿用现有 AbortError 屏蔽逻辑，避免误报。
- **演示为主**：S0-S9 中 S0-S4 走真实数据，S5-S8 为人工可调参驾驶舱（沿用看板已有的人工交互），S9 为同步闭环出口。
